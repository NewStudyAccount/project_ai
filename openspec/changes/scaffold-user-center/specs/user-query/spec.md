## Purpose

向认证中心与其他系统提供稳定的用户查询契约（按 id / 登录名查询与资料查询），支撑登录解析、OIDC 声明组装与业务系统投影。

## ADDED Requirements

### Requirement: 按 id 查询用户
系统 SHALL 提供按 `id` 查询用户基础信息的对内接口；`id` 出参 MUST 为字符串。查询不存在的 `id` 时返回业务失败码。

#### Scenario: 查询存在的用户
- **WHEN** 调用方按存在的 `id` 查询
- **THEN** 返回基础信息（`id`、`username`、状态与基础资料），`id` 为字符串

#### Scenario: 查询不存在的用户
- **WHEN** 调用方按不存在的 `id` 查询
- **THEN** 返回业务失败码与明确提示

### Requirement: 按登录名解析账号
系统 SHALL 提供按 `username` 查询的对内接口，返回账号 `id` 与状态，供认证中心登录解析使用；账号状态（正常/停用/锁定）MUST 原样返回，由调用方裁决。

#### Scenario: 解析成功
- **WHEN** 认证中心按存在的 `username` 查询
- **THEN** 返回该账号的 `id`（字符串）与当前状态

#### Scenario: 登录名不存在
- **WHEN** 按不存在的 `username` 查询
- **THEN** 返回业务失败码，调用方据此走统一的登录失败语义

### Requirement: 用户资料查询
系统 SHALL 提供按 `id` 的资料查询接口，返回展示与 OIDC 声明所需的资料字段；手机号与邮箱 MUST 脱敏输出。

#### Scenario: 查询资料
- **WHEN** 调用方按存在的 `id` 查询资料
- **THEN** 返回脱敏后的资料字段

### Requirement: 统一返回与失败语义
对内查询接口 SHALL 按 `CLAUDE.md` §5.3 返回码分流与统一 `{code,msg,data}` 结构返回；服务不可用时调用方 MUST 能获得明确失败（可降级、可重试语义清晰），禁止把堆栈暴露给调用方。

#### Scenario: 服务不可用
- **WHEN** 用户中心实例不可用而调用方发起查询
- **THEN** 调用方获得明确的失败结果（非挂起），且不包含堆栈信息

### Requirement: 管理写接口鉴权
管理类写接口（创建/更新/启停）MUST 要求已认证的管理身份；对内查询接口仅限服务间调用，不对外匿名开放。

#### Scenario: 未认证调用管理写接口
- **WHEN** 未携带有效访问令牌调用创建用户接口
- **THEN** 按未认证语义拒绝（HTTP 401，系统段错误码）

## Purpose

作为全仓多系统的用户账号权威，管理账号的创建、资料维护、启停与锁定生命周期，并对管理操作留下审计记录。

## ADDED Requirements

### Requirement: 创建用户账号
系统 SHALL 允许已认证的管理操作员创建用户账号：登录名（`username`，全局唯一）与初始资料；创建成功后 MUST 按 `CLAUDE.md` §6.4.5 发号构成分配全局唯一 `id`（出参为字符串），账号初始状态为「正常」。

#### Scenario: 成功创建账号
- **WHEN** 管理操作员提交合法的创建请求（合法且未被占用的 `username`、必填资料齐全）
- **THEN** 创建成功，返回字符串形式的 `id` 与「正常」状态，并记录创建审计

#### Scenario: 登录名重复
- **WHEN** 提交的 `username` 已被占用
- **THEN** 返回业务失败码与明确提示，不创建账号

#### Scenario: 参数校验失败
- **WHEN** 必填项缺失或格式非法
- **THEN** 返回参数校验失败码（`3xxxx`），字段级细节放在 `data`

### Requirement: 资料维护
系统 SHALL 允许管理操作员更新用户资料（姓名、昵称、头像、邮箱、手机、备注）；手机号与邮箱出参 MUST 脱敏。

#### Scenario: 更新资料
- **WHEN** 管理操作员提交对存在账号的合法资料变更
- **THEN** 资料更新成功并记录更新审计

#### Scenario: 敏感字段脱敏输出
- **WHEN** 任何接口返回用户资料
- **THEN** 手机号与邮箱按脱敏规则输出

### Requirement: 账号启停与锁定
系统 SHALL 允许管理操作员将账号状态置为「正常 / 停用 / 锁定」；每次状态变更 MUST 记录审计。即时令牌吊销不在本能力范围（属认证中心）。

#### Scenario: 停用账号
- **WHEN** 管理操作员停用一个正常账号
- **THEN** 状态变为「停用」并记录审计

#### Scenario: 锁定账号
- **WHEN** 管理操作员锁定一个账号
- **THEN** 状态变为「锁定」并记录审计

### Requirement: 管理审计
账号创建、资料更新、状态变更等关键写操作 MUST 记录操作审计（操作人 / 时间 / 动作 / 结果）。

#### Scenario: 写操作留痕
- **WHEN** 任一关键写操作完成（无论成功失败）
- **THEN** 审计中可查到该次操作的操作人、时间、动作与结果

### Requirement: 禁止凭证存储
本系统 MUST NOT 存储密码、凭证密文或任何等价字段；登录验密不属于本系统。

#### Scenario: 数据模型无凭证字段
- **WHEN** 检查用户数据模型
- **THEN** 不存在密码 / 凭证类字段

### Requirement: 管理端操作界面
管理端（`user-admin`）SHALL 提供用户列表（分页与按登录名/状态筛选）、用户详情/编辑、新建用户、启停/锁定操作；界面主键与关联标识 MUST 以字符串处理，所有请求经统一 API 层调用后端。

#### Scenario: 分页浏览用户列表
- **WHEN** 管理操作员打开用户列表并翻页或筛选
- **THEN** 按分页契约（`current`/`size`）返回对应页数据与总数

#### Scenario: 通过管理端新建用户
- **WHEN** 管理操作员在新建表单提交合法数据
- **THEN** 账号创建成功并在列表可见

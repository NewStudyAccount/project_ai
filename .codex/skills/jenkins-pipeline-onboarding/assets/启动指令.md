# 启动指令（复制即用）

> 给 AI 的「一句话」。前提：本技能目录已在该项目的 `.claude/skills/` 下（见下 §0）。
> 目标不是让 AI 少问你，而是让它**按流程走、不猜、在关键点停**。

## 0. 前提：技能得先在项目里

新项目第一次用，先把技能目录复制过去（或用 ai 工具自带的技能安装方式）：

```powershell
Copy-Item -Recurse <来源仓库>\.claude\skills\jenkins-pipeline-onboarding  .\.claude\skills\
```

复制后**开一个新会话**（部分工具的技能目录在会话启动时加载）。没有 `.claude/skills` 支持的工具有兜底：直接让它读技能文件（见 §4）。

## 1. 标准句（推荐）

```
用项目内的 jenkins-pipeline-onboarding 技能，为这个项目接入 Jenkins 流水线：
先跑 bootstrap，再按 SKILL.md 的六步走。仓库地址、端口、镜像仓库、凭据 ID 这些
缺什么就列清单问我，不要猜；到 dry-run 停下让我确认，再往下应用。
```

它锁住三件事：**用哪个技能**（避免走偏）、**不许猜**（缺项必须回头问你）、**在哪停**（应用前确认）。

## 2. 最短句（靠语义触发）

```
给这个项目接入 Jenkins 流水线（用 jenkins-pipeline-onboarding 技能，先 bootstrap）。
```

能触发，但少了边界。风险是 AI 遇到缺失信息时自己编一个——这也是为什么推荐 §1。

## 3. 配置已预填时（零提问）

先把 `deploy/jenkins/jobs.yaml` 的 `defaults` 和 `jobs` 填好，再说：

```
用 jenkins-pipeline-onboarding 技能，按 deploy/jenkins/jobs.yaml 现有内容跑
preflight → dry-run → apply，全绿后按 SKILL 的交付格式汇报；任何 ERROR 就停下报我。
```

## 4. 技能还没搬过去时（一步到位）

```
先把 <来源仓库>/.claude/skills/jenkins-pipeline-onboarding 复制到本项目
.claude/skills/，然后按该技能的 SKILL.md 给这个项目接入 Jenkins 流水线；
缺的仓库地址/端口/镜像仓库/凭据 ID 列清单问我，不许猜，dry-run 之后停下让我确认。
```

## 4.5 装了 slash 命令就直接敲

| 命令 | 用途 |
|---|---|
| `/jenkins:init` | 新项目初始化（只到 dry-run） |
| `/jenkins:add <服务>` | 加一条流水线（下发前会问你） |
| `/jenkins:check` | 体检（只读） |
| `/jenkins:apply [Job]` | 同步到 Jenkins |

命令由 `scripts/bootstrap.ps1` 安装到 `.claude/commands/jenkins/`；源文件在 `assets/commands/`。
## 5. 工具不支持技能目录时（兜底）

```
读 <路径>/.claude/skills/jenkins-pipeline-onboarding/SKILL.md 并严格按它执行：
为这个项目接入 Jenkins 流水线。缺的信息问我，不要猜。
```

## 6. 你仍然要回答的 5 件事（除非预填 jobs.yaml）

| 项 | 为什么要问 |
|---|---|
| Git 仓库地址 | 不能从本地目录推断远端 |
| 默认分支 | 决定 `BRANCH` 默认值与 checkout |
| 镜像仓库地址 | 决定 `IMAGE_REPO`、`docker login` |
| 部署机 IP / SSH 用户 | 决定发布目标 |
| 3 个凭据 ID | 只能引用 Jenkins 里**已存在**的 ID，值不在仓库 |

此外每个服务还要：**端口（须先登记）+ 健康检查路径 + 是否是可部署单元**。

## 7. 怎么判断它真的在按技能走

看它是否产出这四样（缺哪样就是跑偏了）：

1. `deploy/jenkins/` 被 bootstrap 装出来（或说明已存在）；
2. 跑了 `preflight.py` 并**贴出 ERROR/WARN 数**；
3. `--dry-run` 产物路径 + 逐条自查结果；
4. 最终按 `SKILL.md` §3 的固定格式汇报，且明确写「未验证项」。

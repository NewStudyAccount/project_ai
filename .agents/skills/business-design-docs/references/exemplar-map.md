# 范例对照地图：`docs/knowledge-base-design/` 怎么读

> **本文件是项目绑定内容**（登记见 `project-bindings.md` §5）：对照的是本仓库范例产物集与本仓库登记处。
> 移植新项目时**整体替换**为新范例对照，或删除本文件并在 `SKILL.md` §6 表注明。skill 主流程不依赖本文件。

> 范例是本 skill 的**唯一样板**：写新产物前先读对应节，照它的「形态」写，不抄它的「内容」。
> 范例背景：blog 系统的知识库业务域（单进程承载、ES 向量检索、云 API、手动入库、RAG 问答）。

## 2. 范例里「机制」的示范点（比内容更值得学）

1. **推翻留痕**：向量存储 MySQL → ES、自动入库 → 手动入库，旧决策保留在裁决记录并标注「后被推翻」。
2. **清零声明**：开放问题 Q1–Q11 分两批裁决，每批写回写落点，最后「开放问题清单自此清零」。
3. **连带修正**：表数 7→8、`ArticleKnowledgeEvent` 废弃等推翻项，逐条列明改了哪份文档哪一节。
4. **自洽性修正**：唯一键 NULL 处理、跨文档枚举错位、线程池落点合规——这些是 quality-gate 自洽性清单的来源。
5. **登记处联动**：ES 新选型先改 `CLAUDE.md` §2 技术栈；错误码段只在 `docs/error-code-ranges.md` 登记系统号，明细归本域文档；接入信息归 `docs/test-env.md`。
6. **流程边界**：「未获明确指示不创建 openspec 提案」；提案发起后设计文档仍为字段级契约源，提案制品只引用不复制。

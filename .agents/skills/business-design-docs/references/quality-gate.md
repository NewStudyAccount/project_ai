# 质量门与跨文档自洽性检查

> 配合 `SKILL.md` Step 7 使用。验收逐条勾 `assets/acceptance-checklist.md`；本文件是判定口径。
> 方法论出处：项目文档方法论（载体见 `project-bindings.md` §1）§8（质量门）。自洽性清单来自范例产物集（路径见 `project-bindings.md` §5）的**实际踩坑**（主设计 §10「自洽性修正」、table-design §5「遗留」）。

## 1. 产物质量门（逐项过，不过即修）

**结构层**

- [ ] 目录/文件齐全或已注明「不适用 + 原因」；README 职责表状态列与各文档头部状态一致
- [ ] README 声明阅读顺序 + 效力顺序 + 范围一句话
- [ ] 每份文档有「写什么/不放什么」分工声明或引言中的口径指针

**内容层**

- [ ] 主设计：Non-goals、状态机、选型对比（含被推翻方案留痕）、开放问题清单、裁决记录齐备
- [ ] table-design：结论清单先行；DDL 齐套（审计 5 列 / 发号 / 无物理外键 / 索引命名）；偏差/裁决记录；执行约定
- [ ] api-design：全局约定；错误码段位已对照错误码登记处（`project-bindings.md` §2）；接口八元组齐备；接口逻辑含**否定性约束**；错误码明细；变更记录
- [ ] 关键取舍有「决策/取舍/原因」三元组
- [ ] 通用能力按**裁剪源模式**只登记取值差异，未复制通用条文

**契约层**

- [ ] 未复制 L0 契约条文；口径全部指针化
- [ ] 无生产密钥/账密；端口/版本/账密只指向登记处
- [ ] 无凭推导编造的接口/枚举/字段（查不到的标「待核实」）
- [ ] HTML 均有「效力低于正文」声明；原型 token 注释唯一取值处；契约锚点已标注

**流程层**

- [ ] 开放问题状态与裁决记录一致（未决项没被写成定稿）
- [ ] 未获明确指示未创建 openspec 提案
- [ ] 修订场景：变更记录 + 连带修正清单可追溯

## 2. 跨文档自洽性检查（ERROR 必须清零）

逐项对照 README / 主设计 / table-design / api-design / HTML：

| # | 检查项 | 常见错（范例踩坑） |
|---|--------|------------------|
| 1 | **表数一致** | 正文说 7 张、table-design 是 8 张（加表后没连带改） |
| 2 | **状态枚举取值一致** | ES `doc_status=3` 表示失效，但 MySQL `3=FAILED`（跨文档枚举错位） |
| 3 | **唯一键与可空列自洽** | `uk(source, source_id)` + 手动行 `source_id=0` 互相撞键；应置 NULL |
| 4 | **错误码不撞号** | 新段位与既有 `XxxErrorCodeEnum` 已用码重复 |
| 5 | **权限位 / 菜单短号一致** | api-design 权限对照 ↔ table-design 种子 ↔ 原型菜单，三处对不上；短号续号防 `INSERT IGNORE` 静默失败 |
| 6 | **索引/表边界一致** | 检索索引字段与 MySQL 真相源分工表述矛盾（谁是真相源写死一处） |
| 7 | **横切落点合规** | 业务模块自建线程池/JWT 解析/RedisTemplate（违反 L0 横切/反模式约定，落点应统一基础设施层） |
| 8 | **幂等/限流/审计标注齐全** | 关键写接口漏标幂等；管理端写操作漏审计 |
| 9 | **引用指针有效** | 文档互链、章节号、文件名改名后没同步 |
| 10 | **HTML 与正文同步** | ER 图表数/字段旧版；原型 tab 与菜单清单不符 |

**判定：** ERROR（1–7 类）清零才可交付；WARN（8–10 类）在交付回话中列出待办。

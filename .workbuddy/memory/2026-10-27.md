## knowledge-base-design 向量存储改用 Elasticsearch（推翻 MySQL BLOB 方案）

- **用户裁决**：使用 ES（用户明确「使用 ES」）
- **方案**：MySQL `knowledge_chunk` 表去 embedding BLOB（存业务字段 content/heading/embed_status 作真相源），向量+content 镜像存 ES index `knowledge_chunk_v1`（dense_vector 1024 维 cosine HNSW + text `ik_smart` BM25 + RRF 原生混合检索）；检索一条 DSL 内 kNN+match+filter+RRF，命中直接含 content 无需回 MySQL
- **动机**：知识库多技术文档（端口号/表名/类名/配置键），纯向量对精确术语召回弱，BM25+向量 RRF 取长补短；ES 是混合检索不可替代方案（pgvector 无 BM25）
- **代价与对策**：违反 CLAUDE.md §2.2（ES 曾列"明确不引入"）→ 开 openspec 变更前置（§9 Q8，未擅自改项目契约）；ES 运维成本（最重中间件，测试单机单节点）；双写一致性（MySQL 真相源+ES 异步 index+对账补偿 Q11）；中文分词（ik 分词器 Q10）

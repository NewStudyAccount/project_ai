# 双路线自检清单

## 路线 A 自检（初始化项目）

### CLAUDE.md 核心四件
- [ ] 项目名与业务目标明确，有项目边界（明确不做）清单
- [ ] 技术栈完整（前后端分开），有「明确不引入」清单
- [ ] 目录结构：**前端、后端各一棵具体目录树**（每目录有职责一句话），含模块职责表（放什么/不放什么）与目录纪律
- [ ] 开发规范齐备（命名/接口/错误码/DB/事务/安全/日志），每条有落点
- [ ] 无端口、密钥、任务清单混入（应指向登记处）

### 基础内容
- [ ] 基础内容清单经用户逐项确认（RBAC / 登录日志 / 操作日志默认必做；统一认证中心经条件判定后明确做或不做，不默认）
- [ ] 锁定清单登记进 CLAUDE.md（模块 → 代码落点）
- [ ] 各模块按 base-modules.md"必备内容"逐项搭齐（库表/接口/功能点/页面）
- [ ] 模块搭建顺序符合依赖：RBAC → 登录日志 → 操作日志 → 认证中心（如做）；认证做时登录挂接认证中心，无两套登录并存
- [ ] 模块相关待确认口径（超管数据隔离、日志保留期、脱敏字段）已收口进待裁决清单

### 项目骨架
- [ ] 目录树与 CLAUDE.md 逐目录一致，无未登记目录
- [ ] 基础配置文件就位（构建/环境模板/规范配置）
- [ ] 公共代码占位就位（返回体/异常处理/启动入口）
- [ ] 启动/构建/基础模块联调验证通过

### 扩展节
- [ ] 协作红线 + 反模式表已补，或登记在"待补清单"
- [ ] 待裁决事项唯一清单已建

## 路线 B 自检（业务功能开发）

### 设计前置
- [ ] 需求输入来自用户，AI 未推导补充
- [ ] 设计要点提案经用户逐条裁决，有共识确认记录
- [ ] 待裁决项全部收口（裁决或进开放问题清单）
- [ ] 已判定：是否有数据库表变动、是否有前端页面

### 设计制品
- [ ] 三件套齐备，只含已裁决内容
- [ ] business-design：状态机图 + 编号规则（R1…）+ Non-goals
- [ ] table-design：结论清单先行 + 字段裁决说明 + 开放问题唯一清单
- [ ] api-design：每接口八元组 + 否定性约束 + 基础模块接线说明（RBAC 权限点/操作日志埋点）
- [ ] ER 图：有数据库表变动时已生成（mermaid erDiagram，标注主外键与基数）；无变动时已在 README 登记省略
- [ ] 原型图：有前端页面时已生成并标注契约锚点；无页面时已登记省略
- [ ] 可视化与正文一致（不一致处已改图查正文）

### 按设计落码
- [ ] 严格按三件套实现：表结构对 table-design、接口对 api-design、业务规则对 R 编号
- [ ] 基础模块接线完成：接口挂 RBAC 权限点，写操作挂操作日志
- [ ] 无新建 CLAUDE.md 未登记的目录
- [ ] 无设计外功能、无顺手重构；设计偏差已回写三件套（并同步 ER 图）
- [ ] 接口自测含失败分支与错误码；整体联调通过
- [ ] 修 bug 场景：先取报错/日志/traceId，根因定位后最小修改

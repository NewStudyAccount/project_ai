# 路线 A：初始化项目（生成 CLAUDE.md + 搭建项目基础内容）

> 产物：`CLAUDE.md`（核心四件）+ 锁定的基础内容清单 + 项目基础骨架（目录树、基础配置、公共占位、基础模块）+ 验证通过的启动/构建。

## Step 1：收集必填信息（缺什么问什么，不得编造）

| 信息 | 必填 | 缺失时动作 |
|---|---|---|
| 项目名 | 是 | 问用户 |
| 业务目标（一句话）| 是 | 问用户 |
| 项目边界（明确不做）| 是 | 问用户；说不清则列提案待确认 |
| 后端技术栈 | 是 | 问用户 |
| 前端技术栈（纯后端项目可无）| 是 | 问用户 |
| 目录结构约定 | 是 | 用户有既定样式 → 照抄；没有 → AI 按技术栈惯例提案目录树，**用户确认后**才有效 |
| 数据库 / 中间件 | 是 | 问用户 |
| 部署形态（单体/微服务/容器）| 是 | 问用户 |
| **基础内容需求**（RBAC / 登录日志 / 操作日志 / 统一认证中心等）| 是 | 出示 `references/base-modules.md` 默认清单，逐项确认做/不做/改造 |

## Step 2：生成 CLAUDE.md

复制 `assets/claude-md-template.md`，按以下优先级填充：

**核心四件（必填，缺一不可，本步完成即达到"可用"标准）：**

1. **项目概述**：项目名 + 业务目标 + 项目边界（明确不做清单）
2. **技术栈**：前后端选型表 + 「明确不引入」清单
3. **目录结构**：**前端、后端各一棵目录树**（目标形态，含每个目录职责一句话）+ 模块/分层职责表（放什么/不放什么）+ 目录纪律（AI 不得新建未登记目录）
4. **开发规范**：命名、接口、错误码、DB、事务、安全、日志等——每条给出落点

**扩展节（推荐补齐，时间紧可标记后补，但须在文末登记"待补清单"）：**

- 协作红线 + 反模式表（AI 行为护栏，越早补越好）
- 待裁决事项唯一清单（含基础模块的待确认口径，如超管数据隔离、日志保留期限）
- 文档分工表
- **基础内容锁定清单**（模块 → 代码落点）

## Step 3：搭建项目基础内容

严格按 CLAUDE.md §目录结构执行，顺序：

1. **创建目录树**：与 CLAUDE.md 目录树逐目录对应，一个不多一个不少。
2. **基础配置文件**：构建配置（pom.xml / package.json 等）、环境配置骨架（真实密钥不落库，指向配置登记处）、代码规范配置（lint/formatter，如选型包含）。
3. **公共代码占位**（按技术栈适用项）：统一返回体、全局异常处理、基础工具类、启动类/入口文件。
4. **搭建基础模块**：按 `references/base-modules.md` 各模块的"必备内容"逐个实现，依赖顺序：RBAC → 登录日志 → 操作日志 → 统一认证中心（如确认做）。每个模块完成即验证（接口可调、页面可开）。
5. **验证**：后端能编译/启动、前端能构建/启动 dev server、基础模块联调通过。失败则修复后重验，不得带病进入路线 B。

**纪律**：过程中发现目录树不合理（如缺 logs 目录、缺模块），**先回写 CLAUDE.md §目录结构再创建**；顺序不能反。基础模块搭建中出现的设计取舍，写入模块代码同级的设计说明或 table-design（有表变动即走路线 B 的设计前置，不裸写表）。

## Step 4：自检

跑 `references/self-check.md` 路线 A 清单，全部通过后向用户交付：CLAUDE.md + 骨架结构说明 + 基础模块清单与验证结果。

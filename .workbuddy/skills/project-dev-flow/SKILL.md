# 项目开发双路线工作流（搭项目 / 做业务）

## 概述

本 skill 把项目开发拆成两条互斥路线：

- **路线 A「搭项目」**：生成 CLAUDE.md（核心四件：项目名概述、技术栈、前后端目录结构、开发规范）→ 与用户确认基础内容清单（RBAC、登录日志、操作日志、统一认证中心按需）→ 搭建项目基础内容。
- **路线 B「做业务」**：先业务设计（提案 + 裁决）→ 生成三件套与原型图/ER 图 → **按设计直接落码**（无 SDD 制品层，三件套即唯一设计事实源）。

核心纪律：**先设计后落码**；结构类事实只写 CLAUDE.md 一处；AI 不替用户拍板。

方法论深究（四层体系、六条元规则、机制详解）见同项目的 `doc-driven-dev` skill，本 skill 只管执行流程。

## 路线判定

| 用户意图 | 走哪条 |
|---|---|
| 新项目 / 初始化 / 搭项目基础 / 生成 CLAUDE.md | **路线 A** |
| 开发某个业务功能 / 模块 / 业务域 | **路线 B** |
| 想做业务但路线 A 未完成（无 CLAUDE.md） | 先回路线 A 补齐，再进路线 B |

---

## 路线 A：初始化项目（详细步骤见 `references/route-a-init.md`）

1. **收集必填信息**（缺什么问什么，不得编造）：项目名、技术栈（前端/后端分开确认）、业务目标与边界、目录结构约定（用户有既定样式照抄；没有则 AI 按技术栈惯例**提案目录树，用户确认后**才有效）。
2. **生成 CLAUDE.md**（复制 `assets/claude-md-template.md` 填充）：核心四件必填——① 项目概述（项目名、业务目标、边界）② 技术栈 ③ 目录结构（**前端、后端各一棵树** + 职责表 + 目录纪律）④ 开发规范。
3. **确认基础内容清单**（先问再做，默认清单见 `references/base-modules.md`）：
   - 默认必做：**RBAC 框架**、**登录日志**、**操作日志**
   - 条件选做：**统一认证中心**——仅当用户明确需要（多系统统一登录/ token 互认）时进行选型与搭建；单系统项目默认不做，问过才算数
   - 用户增删后锁定清单，登记进 CLAUDE.md
4. **搭建项目基础内容**：按 CLAUDE.md §目录结构执行——创建目录树 → 基础配置 → 公共代码占位 → 按锁定清单逐个搭建基础模块（每个模块的必备内容见 base-modules.md）→ 启动/构建验证。
5. **自检**：跑 `references/self-check.md` 路线 A 清单。

**路线 A 铁律**：CLAUDE.md 未生成前不得搭任何目录；目录结构以 CLAUDE.md 为唯一依据，不得新建未登记的目录；基础内容清单未经用户确认不得开工；脚手架落地后与目录树不一致处回写 CLAUDE.md。

---

## 路线 B：开发业务功能（详细步骤见 `references/route-b-feature.md`）

0. **前置检查**：CLAUDE.md 存在且目录结构明确，否则先走路线 A。
1. **设计前置（必做，不得跳过）**：用户提供需求输入（AI 不推导补充）→ AI 产出「设计要点提案」：领域模型草案、状态机草案、关键取舍（决策/取舍/原因）、待裁决清单（带默认取值）——**此阶段不写任何文档** → 用户逐条裁决 → AI 复述共识 → 用户确认。
2. **生成设计制品**（复制 `assets/l1-starter/` 填充，只写已裁决内容）：
   - 三件套：business-design / table-design / api-design
   - **原型图**（prototype.html）：存在前端页面时**必做**，页面元素标注契约锚点（接口 # / 规则 R 编号）；无前端页面则省略并在 README 登记
   - **ER 图**（er-diagram.html）：存在数据库表变动（新增/修改表）时**必做**，mermaid erDiagram 标注主外键与基数；无表变动则省略并登记
3. **按设计落码**（三件套即唯一设计事实源，无额外制品层）：
   - 阅读顺序：CLAUDE.md → 三件套 → 现有代码
   - 按 api-design 接口清单逐个实现，按 table-design 建表/迁移，按 business-design 状态机与规则（R 编号）写业务逻辑
   - **偏差纪律**：实现与设计冲突时，停下确认；确属设计问题则回写三件套再继续，不得边写边改设计
4. **自检**：跑 `references/self-check.md` 路线 B 清单。

**落码铁律**：① 只实现三件套内的内容，不加未要求的功能，不顺手重构；② 不新建 CLAUDE.md 未登记的目录；③ 待裁决事项必须停下问；④ 修 bug 先取报错/日志/traceId，根因定位后最小修改。

---

## 全局纪律（两路线通用）

1. 单一事实源：结构、口径、清单各存一份，其余指针引用。
2. 效力顺序：CLAUDE.md > 设计正文（三件套）> 可视化（原型/ER）。
3. 待裁决事项**必须停下来问**，不得替用户拍板。
4. 先确认真实契约再实现，不凭推导发明接口/枚举/目录。

# 六大关键机制详解

> 方法论内核的操作细节。写任何文档前先确认以下机制是否落地。

## 1. 分工表机制（防双源漂移的第一道闸）

每个文档头部（或尾部）放一张两列表：

```
| 本文放什么 | 不放什么 |
|------------|----------|
| 业务规则、状态机 | 实现代码、完整枚举表 |
| 库表形态、接口语义 | 生产密钥、端口账密 |
| | 依赖版本（查 version-baseline） |
| | 稳定契约口径（查 CLAUDE.md） |
```

关键动作："不放什么"里写清**该去哪查**——把读者导航到唯一事实源。

## 2. 唯一清单机制

以下内容全项目各存一份、别处只放指针：

- 「明确不引入」组件清单
- 反模式清单
- 待裁决事项清单
- 开放问题清单
- 错误码固定码值登记处
- 端口登记处 / 版本基线 / 测试环境账密

## 3. 裁剪源模式（通用 → 系统取值）

当一份设计跨系统通用（如对象存储策略）：

```
通用设计文档（xxx-design.md）
  = 唯一裁剪源：通用策略、封装、生命周期、安全红线

系统文档（各系统 README 的「裁剪取值」表）
  = 只登记「本系统取值 + 相对默认的差异」，不复制通用条文
```

收益：通用条文改一处全系统生效；系统文档保持轻量且差异一目了然。

## 4. 裁决说明机制（防"优化式破坏"）

关键取舍写「决策 / 取舍 / 原因」三元组：

| 决策 | 取舍 | 原因 |
|---|---|---|
| 主表/详细表拆分 | 拆 | 列表不碰正文元数据；大字段只存对象存储 |
| 大字段不进 DB | OSS | 大字段拖垮列表与备份 |
| 统计字段预留 | 预留 | 本期不做统计；避免后续加列 |

没有这张表，AI（和新同事）会把「预留字段」「故意冗余」「刻意拆表」当瑕疵清理掉。

## 5. 红线 + 反模式表机制

三种纪律，载体不同、缺一不可：

- **红线**（协作纪律，写在 L0）：不可逆操作先征询、不擅自改制品定义、不加未要求的功能、改动最小集、修 bug 先看报错。
- **反模式表**（技术纪律，L0 对照表）：把 AI 真实会犯的错列成「禁止做法 → 正确做法」对照表，每条一句话。
- **待裁决清单**（业务纪律，L0 唯一清单）：AI 遇到必须停下来问，不得替业务拍板。

## 6. 接口级契约技巧

- **寻址约定**：`{idOrSlug}` 先按 id 精确匹配、再按 slug 唯一匹配、皆无按不存在——把歧义消解规则写进契约。
- **出参语义分端**：同一资源管理端返回源文、公开端返回渲染 HTML——显式标注两端字段语义差异。
- **否定性约束**："不改 X""不碰 Y""忽略 Z"要逐条写明——AI 对"不做什么的指令"比对"做什么"更敏感。
- **接口逻辑编号化**：校验 → 落库 → 审计 → 失败分支（错误码），每步可被任务引用。

# 产物集骨架与写作要领

> 配合 `SKILL.md` §3 使用。范例：本仓库业务设计产物集（路径见 `project-bindings.md` §5，逐节对照见 `exemplar-map.md`）。
> 通用方法论（分工表、唯一清单、裁剪源、效力顺序）见项目文档方法论（载体见 `project-bindings.md` §1）§5–6，本文件不复述其条文，只给**骨架与落法**。
> 本文只用泛称（「L0 契约」「各登记处」）；具体载体见 `project-bindings.md`；模板默认值的口径来源见 `project-bindings.md` §4。

## 1. 目录与命名

```
docs/<domain>-design/
├── README.md                 # 索引（必备）
├── <domain>-design.md        # 主设计（必备；与目录同名）
├── table-design.md           # 库表契约（有落库时必备）
├── api-design.md             # 接口契约（有接口时必备）
├── <domain>-er-diagram.html  # ER 图（有表时建议）
├── <domain>-prototype.html   # 页面原型（有界面时建议）
├── <domain>-dataflow.html    # 数据流图（链路复杂时可选）
└── <domain>-<topic>.html     # 科普/说明（可选，非契约）
```

- `<domain>`：kebab-case，与目录、主设计、HTML 前缀一致（范例 HTML 用了缩略前缀 `knowledge-`，新产物建议全名前缀保持一致）。
- 新目录先跑模板实例化再填内容：

```powershell
powershell -NoProfile -File .claude/skills/business-design-docs/scripts/new-domain-design.ps1 `
  -Domain <domain> -DomainCn "<中文名>" [-System <system>] [-Database <db>] [-DryRun]
```

占位符：`{{DOMAIN}}` / `{{DOMAIN_CN}}` / `{{SYSTEM}}` / `{{DB}}` / `{{DATE}}`；模板即骨架，章节内容按本文件要领填充，可按域裁剪章节（**裁剪要在 README 职责表注明**）。

**状态标记约定**（README 状态列 + 各文档头部）：

| 标记 | 含义 |
|------|------|
| 探索稿 vN.N | 有开放问题；N 随裁决批次递增 |
| 探索稿 vN.N（开放问题清零） | 裁决完成、尚未进入字段级定稿 |
| 设计稿 | 字段级契约（table/api-design）落定 |
| 已归档/已实施 | 实施完成后按变更回写（本 skill 不管实施） |

## 2. `<domain>-design.md`（主设计）骨架

| 章节 | 内容 | 要领 |
|------|------|------|
| 头部引言 | 状态 / 定位 / 前置材料 / 索引指针 | 一行声明效力口径以 L0 契约为准 |
| 1. 背景与目标 | 业务背景；**1.1 分期目标**（P0/P1/P2 表）；**1.2 非目标 Non-goals** | Non-goals 与正向需求同等重要；对齐 L0 项目边界 |
| 2. 现状盘点（可复用资产） | 资产 / 现状 / 本域如何复用 | 逐项**取证**，不确定标「待核实」 |
| 3. 总体数据流 | ASCII/文字全链路（分阶段：主流程 + 异步 + 治理） | 与 `<domain>-dataflow.html` 同步 |
| 4. 领域模型 | mermaid 图 + 核心概念表 + **4.1 状态机** | 状态枚举值与 table/api-design 一致 |
| 5. 关键选型对比（决策记录） | 每个选型：候选对比表 + 裁决 + 理由 + 代价 | 被推翻的方案也留痕（防反复） |
| 6. 库表与索引设计（草案） | 每表一节摘要（字段/类型/说明） | 头部明示「字段级契约见 table-design.md，冲突以其为准」 |
| 7. 接口草案 | 分端摘要（管理端/用户端/内部契约） | 明示「详细契约见 api-design.md」 |
| 8. 实施切期 | P0-x 切期表（前置登记 + 骨架 + 链路 + 前端） | 只写切期建议，不写任务清单（tasks 归 openspec） |
| 9. 开放问题清单 | 编号 Q1…Qn + 裁决批次 + **清零声明** | 唯一清单；见 `decision-mechanism.md` |
| 10. 裁决记录 | 日期 / 决策 / 依据 三列（含被推翻的决策） | 与 9 联动；见 `decision-mechanism.md` |

## 3. `table-design.md` 骨架

| 章节 | 内容 | 要领 |
|------|------|------|
| 头部引言 | 状态 / 口径指针（审计 5 字段、发号、`id` 对外 String、无物理外键、`uk_` 不做幂等、单表索引等 → L0 数据规范，节号见 `project-bindings.md` §1）/ SQL 落点约定 | 口径**指针**，不复述条文 |
| 1. 结论清单（先看这个） | 1.1 既有表改不改（逐表结论）；1.2 新增表清单（# / 表名 / 用途 / 必要性 / 设计正文指针）；1.3 库与组件落点 | 结论先行，30 秒抓住全貌 |
| 2. 新增表结构（DDL） | 每表一节：DDL 代码块 + 字段说明 + 索引/唯一键 + 应用层约束 | `IF NOT EXISTS`、`ENGINE=InnoDB DEFAULT CHARSET=utf8mb4`、审计 5 列齐套、无物理外键 |
| 3. 检索索引定义（如有） | mapping / 字段语义 / 与 MySQL 表的真相源分工 | 明示「业务字段真相源在 MySQL，向量/索引为镜像」类边界 |
| 4. 种子清单 | RBAC 菜单/按钮短号表（续号避撞）；配置引导默认；索引初始化 | 短号与 `api-design` 权限对照表一致 |
| 5. 与设计正文的偏差 / 裁决记录 | # / 项 / 裁决方向 / 落点 + **连带修正（已同步）** 尾注 | 与主设计不一致**必须**在此登记，禁止隐式改契约 |
| 6. 执行约定 | 建表/种子/索引顺序；可重复执行；不可逆操作征询；冒烟验证顺序 | 对齐 L0 协作红线（生产执行前征询） |

## 4. `api-design.md` 骨架

| 章节 | 内容 | 要领 |
|------|------|------|
| 头部引言 | 状态 / 契约口径指针（L0 接口与基础契约，节号见 `project-bindings.md` §1）/ 鉴权形态 / 路由形态 | 指针，不复述 |
| 0. 全局约定 | 前缀 / 返回体 / 分页 / id 类型 / 失败语义 / 内容类型 / 幂等 / 时间 / 枚举 / 审计 | 一行一项；本域 clamp、特例在此登记 |
| 0.1 本域业务错误码段位 | 段位 / 域表 + 与既有枚举**零撞号**声明 | 先查错误码登记处（`project-bindings.md` §2）；新系统号先登记 |
| 0.2 状态枚举（接口透出值） | 枚举 / 取值 / 说明 | 与 table-design、主设计状态机一致 |
| 1..n 按资源分节 | 每接口**八元组**：接口名 / 方法·路径 / 权限 / 幂等 / 入参 / 出参 / 接口逻辑 / 使用表 | 逻辑=编号步骤（校验→落库→审计→失败分支错误码）+ **否定性约束**（“不碰 X”） |
| 特殊帧契约（如有） | 如 SSE 帧格式表：事件类型 / data 字段 / 时序 | 帧格式是**契约**，逐字段写 |
| 权限位与菜单对照 | 权限位 / 用途 / 菜单·按钮短号 | 与 table-design §4 种子一致 |
| 错误码明细 | code / 枚举名 / 文案 / 典型场景 | 新码先在本表分配再落枚举 |
| 效力与变更 | 效力顺序声明 + 未定稿项 + **变更记录**表 | 主设计草案以本文件为准 |

## 5. `README.md` 骨架

必备元素（顺序即范例顺序）：

1. **文档职责表**：文档 / 职责 / 状态（+ 每行可加效力层级）。
2. **范围一句话**：一段话讲清「在哪个系统、什么链路、什么形态、什么边界」。
3. **状态**：探索稿/设计稿 + 裁决批次摘要（含「开放问题清零」声明）。
4. **阅读顺序** 与 **效力顺序**（两条都要，防效力倒挂）。
5. **流程约定**（如有）：openspec 提案是否已发起、设计文档与提案制品的分工。
6. **相关既有材料**：路径 / 关系（指针表，含 L0 契约、通用裁剪源、RBAC、token、各登记处）。

## 6. HTML 可视化四件的统一约定

| 约定 | 要求 |
|------|------|
| 自包含 | 单文件内联 CSS/JS，浏览器直接打开；`lang="zh-CN"` |
| 页脚声明 | 「效力低于设计正文」（科普类加「非契约」） |
| 同步关系 | ER ↔ table-design；数据流 ↔ 主设计 §3；原型 ↔ api-design + 菜单清单 |
| 视觉 token | 原型取视觉 token **唯一取值处**（`project-bindings.md` §2）子集，**注释出处** |
| 契约锚点 | 原型元素标注对应接口/规则（如「→ POST /api/v1/...」） |
| 差异登记 | 实装/正文与 HTML 不一致处回写 README 或正文（范例：原型 hero 统计条属可选装饰） |

壳层骨架在 `assets/templates/*.html.tmpl`（er-diagram / prototype / dataflow）；科普类无定式，仿范例 `<domain>-<topic>.html`。

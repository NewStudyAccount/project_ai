① 入库（doc → PENDING）

来源 A · 文章（管理端手动选择入库） blog-admin「文章入库」页列出已发布文章(未入库/已入库/待更新) → 勾选提交 POST /admin/knowledge/docs/from-articles（无事件，blog 逻辑零改动）
⬇
knowledge_task(INGEST) → 入库一步到位 doc upsert(PENDING) · 经 ArticleContentProvider 同进程只读回拉正文+标题/分类/标签
来源 B · 手动导入（管理员） blog-admin 上传 .md(多选)+标签 → POST /admin/knowledge/docs · 源文 put MinIO → knowledge_file 登记
⬇
doc 登记 source=MANUAL → 从 MinIO 读源文
共用切块
⬇
切块器 按标题层级+段落聚合 · 500–800 字/chunk(Q3) · content 含上下文增强前缀
⬇
knowledge_chunk（MySQL blog_db） seq / heading / content（真相源）· embed_status=PENDING · 主键=ES 文档 _id

② 向量化 + 入 ES（独立线程池）

knowledge_chunk（PENDING）逐 chunk 读业务字段 → 批量调 EmbeddingProvider
⬇
EmbeddingProvider.embed(texts[]) 云 API · SiliconFlow bge-m3 · 1024 维 · 免费额度，节流+失败可重试
⬇
index 进 ES（异步） chunk_id 为 _id 幂等覆盖 · dense_vector(cosine/HNSW) + content(BM25/ik) + 元数据
ES index 成功回写 MySQL embed_status=READY · 全部 READY 且 ES index 完成 → doc.status=READY
失败 → embed_status=FAILED + fail_reason单块可重试 · 对账任务扫描补偿(Q11)
⬇
ES index knowledge_chunk_v1chunk_id / doc_id / heading / content / embedding / source / tags / doc_status + doc_title / doc_url

③ 检索 + 生成（登录问答，SSE）

⬆ 输入
用户问题 q POST /knowledge/ask?sessionId · 登录限流(20次/天+5次/分)
⬇
EmbeddingProvider.embed(q) 问题向量化（失败→如实报错，语义检索无降级）
⬇
ES 检索 kNN + BM25 + RRF knn(embedding,q) · match(content,q) · filter(doc_status=READY) → RRF 融合 → Top-K(含 content + doc_title/doc_url，无需回 MySQL)
⬇
组装上下文 + 出处chunk.content + 出处取自 ES denormalize 的 doc_title/doc_url（全链路不回 MySQL）· LLM 不可用→降级 ES match 关键词+模板回答(Q6)
⬇
LLMProvider.chat(prompt, stream) 云 API 流式 · 独立线程池
⬇
SSE 流式返回 portal 答案流式 + 末尾 refs[] 引用来源 · 会话记录落 knowledge_chat_* · ES 不可用→直接 503 无降级

④ 同步治理

文章下架 / 删除（管理端手动失效）「失效」按钮或对账 → doc INVALID + ES 文档 doc_status=4（不物理删，检索 filter 排除）· 无自动事件
文章重发布 / 手动导入编辑（待更新）「文章入库」页识别 content_version 变化 → 复用 doc 行重建 · 删除 ES 旧 chunk 文档
重建索引（单文档 / 全量）删 ES index 重建 + MySQL embed_status 全重置 + 重切 + 重向量化（换 provider/model 后）
对账补偿 / article-index/sync已发布文章 diff → 待更新 · 已下架/删除 → INVALID + ES 置 4 · 失败任务重跑(tasks/rerun)
统计 / 健康度doc/chunk 数、READY 比例、ES 文档数、provider 调用量
关键不变量：
  • 边界隔离：ES 仅用于 knowledge 域一个 index knowledge_chunk_v1；blog 文章列表/分类/标签检索仍走 MySQL，不扩。
  • 真相源：MySQL chunk 业务字段为真相源，ES content+vector 为检索镜像；ES index 失败可凭 content 重建向量+重 index。
  • 单进程只读契约：仅 ArticleContentProvider(blog-knowledge-api，blog-service 只读实现)；无事件、不改 blog 既有逻辑；入库/失效全部管理端手动触发；拆独立进程时切 Feign，业务代码不变。
  • 向量不落 MySQL：MySQL chunk 表不再存 embedding BLOB，向量在 ES；切换 provider 须重建索引。
  • 队列/限流：AI 调用走独立 ThreadPoolTaskExecutor(core2/max8)，线程池满→429；问答限流 20次/天 + 5次/分/用户。

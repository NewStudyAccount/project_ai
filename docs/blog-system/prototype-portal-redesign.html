blog-portal 用户端 · 页面重设计（极光阅界）
设计依据：business-design §5.2/§6 · api-design §6 · portal-aurora-visual（token 子集取 tokens-aurora.css） · content=服务端渲染 HTML（api-design §6.4） · 效力低于设计正文，原型不覆盖契约

重设计目标：从「能看」到「好读」

现行 blog-portal 是 960px 裸卡片流——信息能出来，但阅读体验和品牌感都停在「骨架即成品」。 本次以 阅读体验 与 契约驱动布局 两条主线重排用户端六路由，视觉语言延续极光 Aurora token， 明确不套管理端壳（portal-aurora-visual 要求）。

三条设计主线

  • 阅读优先：详情页 760px 阅读列 + 1.88 行高 + 完整正文排版体系（h1–h4/图片/引用/代码/表格）
  • 契约驱动：每个区块标注数据来源，设计不虚构字段（无接口支撑的元素一律不做）
  • 品牌轻量：token 子集延续 Aurora，门户壳保持白底轻盈，不搬管理端侧栏/胶囊语言

布局骨架（对齐 business-design §6）

  • 首页/列表：1120px 双栏（主内容 + 292px 侧栏）
  • 详情/关于：808px 居中阅读列，去侧栏去噪
  • 站点头部 60px：品牌 + 5 导航 + 搜索（keyword→/articles）
  • 六路由：/ · /articles · /articles/:idOrSlug · /categories · /tags · /about

相对现状的改动

  • 封面图上位：coverFileId→/api/v1/public/files/{id}（现状从未渲染）
  • 置顶从「文字列表」升级「精选卡区」（isTop=1）
  • 详情正文从 3 条样式扩展为完整排版体系，直接吃服务端渲染 HTML
  • 列表补筛选状态 chips、分页、共 N 篇；标签云带计数权重

Spring Cloud 网关鉴权实践

qjj· 2026-10-12 10:20· 技术 / 后端· 2,180 字
Spring网关

一级标题

鉴权职责切分

网关是唯一鉴权点：认证（JWT/会话）、登录态与路由级放行/拒绝、身份注入 X-User-*。业务服务不做登录/验签/注解拦截，只信网关注入值。

业务服务不得信任可伪造的客户端 X-User-Id；服务内以网关注入（覆盖写入）的值为准。

请求链路

  1. 浏览器 → Nginx：TLS、静态资源、反代 /api
  2. 网关：鉴权、注入 X-User-Id / X-User-Name、TraceId
  3. 业务服务：参数校验 → Service → Mapper；关键写 @Idempotent
  • 未登录 → 401 + 系统段「未认证」
  • 无权限 → 403；业务失败 → HTTP 200 + 业务码

配置样例

yamlspring:
  cloud:
    gateway:
      routes:
        - id: blog-public
          uri: lb://blog-service
          predicates:
            - Path=/api/v1/public/**

接口约定速查

场景HTTPcode 语义
未登录4011xxxx 未认证
业务失败2002xxxxx 业务码
限流429请求过于频繁
